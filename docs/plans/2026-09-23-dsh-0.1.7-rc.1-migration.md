## 上一轮为何停在 pending（历史）

上一轮认为 RC1-04/27 需要「持久化模型的架构重写」且无法从卡片高置信推出目标接口。本轮借助同批
已迁移插件（`dsh-tools-manager` 的动态数组 volatile Config + 自建 HTTP/RPC 网关 + `settings.update`；
`dsh-interpreters` 的 `source()` 桥；`dsh-plugin-sidebar-brand-text` 的 `plugins.row.config`）确认了
范式，因此不需要推倒数据模型：**profile 数组整体作为单个 volatile Config 字段**，读写面不变。

## 校验环境（可复现）

本插件 devDependencies 不声明任何 `@deepseek-ai/*`，`prebuild` 跑 `scripts/relink-deps.mjs` 把
`node_modules/{cordis,@deepseek-ai/*}` 建成 junction 指向 `~/.dsh/source/current`（本地只读 `dsh/`，
0.1.5-rc.2）。因此 `pnpm typecheck` / `pnpm build` 的 tsc 腿只验 0.1.5（详见「dev 树滞后」）。

rc.1 静态校验配方（本轮使用，收尾已删除探针配置）：

1. `%TEMP%\opencode\ys-rc1` 安装 registry `next` 全量包（`0.1.7-rc.1`，含
   `@deepseek-ai/cordis@4.0.4`、`@deepseek-ai/schemastery@3.18.4`）。
2. 临时 `tsconfig.rc1-probe.json` = `extends ./tsconfig.json` + `paths` 指向该目录的
   `node_modules/@deepseek-ai/*/lib/types/*.d.ts`（含 `/client` 与 `/types` 子路径）。
3. `pnpm exec tsc --noEmit -p tsconfig.rc1-probe.json`；`lib/types` 也用同一探针
   （去掉 `--noEmit`）在 rc.1 类型下重新生成。

### 关于「动态 profile 列表持久化」的决策

`dsh-tools-manager` 已证明「用户可增删的数组」可以整体作为单个 `.volatile()` Config 字段（它用
`z.array(z.string()).default([]).volatile()` + `settings.update(ns, {disabled})`）。本插件照此把
`profiles` 整个数组作为 volatile 字段，**不推倒 ProfileStore 的数据模型**，只把持久化面从
`SettingsScope.replace()` 换成 `settings.update()`，CRUD/校验/迁移逻辑保持不变。

### 入口 row id 与旧数据连续性

新模型的 settings namespace = profile entry id。为让宿主的 `$DSH_HOME/settings.yaml` 一次性导入把旧
`ya-subagent` 段映射到本 entry，`cordis.patch.yml` 的 row id 保持/设为 **`ya-subagent`**（旧
namespace 同名），而非 `yet-another-subagent`。`plugins.row.config` key 相应为
`@huanlin/dsh-plugin-yet-another-subagent#ya-subagent`。

## pending / 残余风险

1. **运行时未在 rc.1 真机验证**：无 0.1.7-rc.1 运行中的 host；客户端 slot/projection/navigation 改动
   （尤其 `uiWorkspace.openSession(address)` 对 'unknown' mode、`refreshProjections` 的加载时机）只过静态
   检查。需在 0.1.7-rc.1 `dsh web` 上验证：Plugins 页配置卡、toolcall 卡三分支、子代理树、点击打开子会话。
2. **旧 `settings.yaml` 导入的形状校验**：宿主按 entry schema 校验导入段；旧段里的 legacy profile 形状
   （`persona: string`、`toolFilter: {allow,deny}`）可能被 schema 拒绝并留在 `settings.yaml.imported`。
   `resolveProfiles`/`migrateProfile` 能做形状迁移，但发生在 schema 校验之后——若真机复现，需要在导入前
   手工改写旧段或给 schema 加兼容联合。
3. **dev 树/CI 校验缺口**：`tsconfig.typecheck.json` 仍指向本地 0.1.5 checkout，常规 `pnpm typecheck` 不
   可信。建议后续把 devDependencies 提升为 rc.1 registry 包（或引入 registry cohort CI），本次按任务约束
   「devDeps link 路径不得变化」未改。
4. `generalFixed` 从旧的持久化字段降级为 seed-only（非 volatile），旧的 `generalFixed:false` 只能通过
   `cordis.patch.yml` 表达。
